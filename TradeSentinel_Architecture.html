TradeSentinel

System Architecture & Trading Flow

TradeSentinel is an autonomous, multi-agent artificial intelligence system designed for secure, real-time trading on the Binance network. Instead of a monolithic bot, the system is separated into three highly specialized AI agents working sequentially. This separation of concerns ensures that the AI reasoning is strictly bounded by hardcoded programmatic risk controls.

2. Component Deep-Dive

Agent 1: The Scout (Perception Layer)
The Scout agent acts as the eyes and ears of the system. It continuously polls the Binance Web3 Open APIs and the Model Context Protocol (MCP) servers. It aggregates real-time order book depth, candlestick data (OHLCV), volume metrics, and breaking market news. It formats this multi-modal raw data into a clean, contextual JSON package.

Agent 2: The Strategist (Reasoning Layer)
The Strategist is the brain. It takes the structured data package from the Scout and injects it into a highly specialized prompt harness sent to a Large Language Model (LLM). The LLM analyzes market sentiment, technical indicators, and momentum. It does not trade directly; rather, it outputs a "Trade Intention" (e.g., BUY BTC, 0.5 risk weight, due to high order block demand).

Agent 3: The Executor (Risk & Execution Firewall)
The Executor is the most critical component. It intercepts the "Trade Intention" from the Strategist and runs it through a gauntlet of hardcoded Python risk checks. It verifies daily drawdown limits, enforces a maximum portfolio allocation per trade (e.g., 5%), and calculates an mandatory stop-loss. Only if all risk conditions are met does the Executor sign and execute the transaction via the Binance API.

3. Data State & Reproducibility

To ensure full transparency during live operations, the system features a built-in Audit Trail logger. Every complete cycle writes to an immutable local JSON log containing the exact timestamp, the market data perceived by the Scout, the exact prompt/response from the Strategist LLM, and the final execution status (or rejection reason) from the Executor. This guarantees that the agent's "thought process" is 100% reproducible and verifiable.
